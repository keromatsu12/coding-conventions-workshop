# コードの臭いカタログ（17-2）

**臭い = 必ずしも悪ではないが、問題が隠れている可能性が高いサイン。**
指摘するときは臭いの名前を使うと、何が問題で何をすればよいかが共有しやすい。

| 臭い | 見分け方 | 何を疑うか | 対処（参照章） |
| --- | --- | --- | --- |
| 長すぎる関数 | 画面に収まらない、「ここから〜」コメント | 責務過多 | 関数の抽出（第3章） |
| 巨大なクラス（神クラス） | 何でも知っている、変更理由が複数 | 凝集度の低さ | クラス分割（第4・5章） |
| 長い引数リスト | 引数4個以上、boolean引数 | 責務過多／まとまりの欠如 | オブジェクト化 |
| 重複コード | 同じロジックが複数箇所 | DRY違反 | 共通化（※3回目から） |
| 深いネスト | if/for が3段以上 | 制御フローの複雑さ | 早期リターン（第3章） |
| 巨大な if/switch 連鎖 | 種類ごとの分岐が増え続ける | OCP違反 | ポリモーフィズム（第5章） |
| 不適切な名前 | `data` `tmp` `Manager` | 設計の曖昧さ | 改名（第2章） |
| 特徴の横恋慕 | 他クラスの値ばかり参照する | 責務の置き場所が違う | メソッドの移動 |
| データの群れ | いつも一緒に渡る引数の組 | 概念が抽出できていない | 値オブジェクト化 |
| 変更の発散 | 1つの変更で複数箇所を修正 | CCP違反 | パッケージ再編（第7章） |
| 散弾銃手術 | 1つの概念が全体に散らばる | 責務が散らばっている | 集約する |
| コメントだらけ | 「何を」を説明するコメント | コードが説明不足 | 名前と分割で解消（第2章） |
